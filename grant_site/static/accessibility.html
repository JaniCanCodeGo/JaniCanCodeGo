Accessibility Statement

Grant Writing Studio is built to conform to Section 508 of the Rehabilitation Act (36 C.F.R. Part 1194, revised 2017), which incorporates WCAG 2.0 Level AA; we target the stricter WCAG 2.1 Level AA throughout.

Measures in place

  • Semantic HTML landmarks (header, nav, main, footer) and a logical heading hierarchy on every page (WCAG 1.3.1, 2.4.6).
  • “Skip to main content” link as the first focusable element (2.4.1).
  • Every form control has a programmatically associated <label>, with hints linked via aria-describedby (1.3.1, 3.3.2, 4.1.2).
  • All functionality is operable by keyboard alone; focus indicators are visible at 3px with high contrast (2.1.1, 2.4.7); focus is managed to the progress and results regions as the agent runs (2.4.3).
  • Live agent status is announced to screen readers via role="status"/aria-live="polite"; errors use role="alert" (4.1.3, 3.3.1).
  • Color contrast meets or exceeds 4.5:1 for text and 3:1 for large text and UI components in both light and dark themes (1.4.3, 1.4.11); color is never the only indicator (1.4.1).
  • Layout reflows to 320 px width without horizontal scrolling; text can be resized to 200% (1.4.4, 1.4.10); touch targets are at least 44×44 px (2.5.5 AAA, met as best practice).
  • Respects prefers-reduced-motion; no content flashes (2.3.1).
  • Data tables use caption and scoped headers (1.3.1); links that open new tabs say so to screen readers (3.2.5 best practice).
  • Page language declared (lang="en") and descriptive page titles (3.1.1, 2.4.2).
  • Documents generated for download are produced in Markdown and Word (.docx) with true heading structure so they remain accessible (508 E205 electronic content).

Testing

The interface is verified with keyboard-only navigation and automated heuristics; deployments should additionally run axe-core/ANDI and screen-reader passes (NVDA, JAWS, VoiceOver) as part of their 508 assessment. The agent also performs a heuristic 508 spot-check of your organization’s website as part of every run.

Feedback

If you encounter an accessibility barrier, contact the operator of your deployment. Please describe the page, the assistive technology and browser used, and the problem; we aim to respond within two business days and to remediate promptly.
